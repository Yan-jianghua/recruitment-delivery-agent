# 企业接入与安全基线

版本：V1.0
日期：2026-11-07
状态：规划基线，待甲方确认

## 目标

企业接入必须让数据、身份、权限和操作责任留在可控边界内。系统先支持只读接入和动作预览，再根据真实业务价值增加受控写入。任何连接器都不能把企业内网、生产数据库或管理员权限直接交给 Agent。

## 接入对象

首批对象按外贸与供应链流程建模。

| 对象 | 典型来源 | B0处理 | B1以后 |
| --- | --- | --- | --- |
| 客户与询盘 | CRM、Excel、邮件 | 合成快照 | 只读同步 |
| SKU与商品资料 | ERP、OMS、商品库 | 合成文档 | 只读同步 |
| 供应商与采购 | ERP、采购系统 | 合成快照 | 只读同步 |
| 订单与报价 | ERP、OMS、CRM | 合成快照 | 只读 API |
| 库存与生产进度 | WMS、ERP、MES | 合成快照 | 只读 API 或视图 |
| 单证与合同 | 文件盘、OA、对象存储 | TXT 文档 | 受控文件连接器 |
| 出货与物流 | TMS、货代系统 | 合成物流事件 | 只读 API 或文件导入 |
| 协同任务 | OA、企业微信、钉钉、飞书 | 只生成预览 | 受控任务写入 |

## 接入顺序

1. 使用 CSV 或 Excel 和模拟 API 验证对象模型、版本、权限和异常规则。
2. 接入一个企业系统的只读 API 或客户批准的数据库视图。
3. 加入同步游标、字段映射、失败重试、数据新鲜度和对账记录。
4. 只开放一个低风险写入动作，例如创建待跟进任务或回写订单备注草稿。
5. 经过甲方签收后，再评估其他写入动作。

优先级取决于目标企业现有系统和最耗时的业务步骤。没有客户授权时使用模拟器，演示材料必须明确标记为模拟。

## 连接器契约

每个连接器必须写入以下元数据。

| 字段 | 说明 |
| --- | --- |
| connector_id | 连接器唯一标识和版本 |
| source_system | ERP、CRM、WMS、TMS、OA 或文件源 |
| tenant_id | 所属租户 |
| auth_ref | 密钥管理系统中的凭据引用，不保存明文 |
| allowed_objects | 允许读取的对象列表 |
| field_mapping | 外部字段到内部字段的映射 |
| data_classification | 字段分类和可出域范围 |
| sync_mode | API、视图、文件、Webhook 或定时同步 |
| cursor | 最后成功同步位置 |
| last_success_at | 最后成功时间 |
| failure_state | 错误码、重试次数、人工处理状态 |

连接器的读取结果必须包含外部系统、外部 ID、数据版本或更新时间、来源链接或定位、同步时间和字段映射版本。缺少时间或版本的数据不能被回答当成当前事实。

## 工具分级

| 等级 | 动作例子 | 默认策略 |
| --- | --- | --- |
| T0 | 查询订单、库存、制度、物流节点 | 可自动读取，返回来源和时间 |
| T1 | 创建跟进任务、生成报价草稿、添加订单备注预览 | 生成预览，业务负责人确认 |
| T2 | 修改订单、改价、变更供应商、发送外部消息 | 强制审批、幂等键、执行后核验 |
| T3 | 删除生产数据、全量导出敏感数据、任意 SQL 或脚本 | 永久拒绝 |

Agent 只能调用白名单工具。每个工具需要输入 Schema、输出 Schema、最小权限凭据、超时、重试上限、幂等策略、敏感字段规则和审计事件类型。

## 写入流程

写入类动作采用 `plan → preview → approve → execute → verify`。预览要显示目标系统、对象、字段变化、影响范围、发起人、审批人、策略版本和幂等键。执行前再次检查身份、权限、对象版本、审批有效期和预算。执行失败时先查询结果，再决定补偿或人工处置，不能因为网络超时就重复提交。

B0 只保存预览和审批记录，禁止真实外部写入。B1 至 B3 每增加一种写入动作，都要增加动作专属的正例、拒绝例、重复请求、超时、未知结果、补偿和回滚测试。

## 身份和权限

正式部署使用企业 IdP。浏览器入口采用 OIDC/OAuth 2.0 授权码流程并启用 PKCE，服务端验证签发方、受众、签名、过期时间、租户和主体状态。组织成员可以通过 SCIM 或客户批准的 API/CSV 同步，离职和禁用需要有明确的传播时限。

每次检索、引用、导出、工具调用、审批和写入都重新计算以下决策输入。

```text
subject: {tenant_id, user_id, groups, status}
resource: {resource_type, resource_id, data_classification}
action: read | search | export | invoke_tool | approve | write
context: {request_id, client, source_ip, purpose, time}
policy_version: 当前策略版本
```

请求正文中的 `tenant_id`、`user_id`、角色和权限字段不参与身份确定。管理员的授权管理能力与正文阅读权分开。默认拒绝。数据库表带 `tenant_id`，子资源和父资源通过复合约束保持同租户关系。PostgreSQL 行级安全可以作为纵深控制，应用层授权仍然必须执行。 [PostgreSQL Row Security Policies](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

## 数据和模型边界

- 原始文档和业务数据优先保存在企业控制的数据库和私有存储中。
- 传输使用 TLS，存储加密，敏感字段在日志和模型上下文中脱敏。
- 模型供应商、数据区域、训练使用、保留和删除策略在环境契约中登记。
- 外部文档、邮件、网页、检索片段和模型输出都视为不可信输入。
- 系统规则与资料内容分层，资料内容不能覆盖权限、工具白名单或审批要求。
- 凭据只以密钥引用进入应用，真实密钥放在客户批准的密钥管理系统中。
- 日志不记录 token、密码、完整身份证号、完整银行卡号和不必要的业务正文。

## 审计与可观测性

审计事件至少包含主体、租户、资源、动作、结果、策略版本、模型或连接器版本、时间、`request_id` 和 `trace_id`。需要覆盖登录、授权变化、导入、检索、引用、模型调用、工具计划、审批、执行、失败、撤销、删除和导出。普通用户不能修改审计事件，审计查询本身也要受权限控制。

使用 OpenTelemetry 串联 API、授权、检索、模型和连接器。至少监控授权拒绝率、越权测试通过率、引用支持率、检索延迟、工具成功率、审批耗时、连接器失败率、撤权生效时间和敏感信息拦截次数。 [OpenTelemetry Observability Primer](https://opentelemetry.io/docs/concepts/observability-primer/)

## 安全验收

| 类别 | 验收例子 | 放行条件 |
| --- | --- | --- |
| 租户隔离 | 跨租户搜索、详情、引用、导出和任务查询 | 所有负例拒绝且无正文泄露 |
| 对象权限 | 员工、主管、管理员和审计员访问同一订单 | 结果字段和动作按角色受限 |
| 撤权 | 撤销文档或订单权限后访问历史答案和缓存 | 新请求立即阻断，记录权限版本 |
| 提示注入 | 恶意文档要求导出其他租户或调用高风险工具 | 工具层拒绝并保留审计 |
| 凭据保护 | 日志、错误、导出和模型上下文扫描 | 不出现密钥、完整令牌和敏感字段 |
| 连接器故障 | 超时、重复、迟到、断线和错误响应 | 有界重试、可查询状态和人工处理入口 |
| 写入安全 | 重复提交、对象版本变化、审批过期 | 拒绝陈旧操作，保持幂等和审计 |
| 删除恢复 | 删除、备份恢复、索引重建并发 | 删除墓碑和权限撤销优先生效 |

安全要求采用 OWASP ASVS、OWASP LLM 风险清单和 NIST AI RMF 组织，首版不宣称通过认证。 [OWASP ASVS](https://asvs.owasp.org/)、[OWASP Top 10 for LLM Applications](https://owasp.org/www-project-top-10-for-large-language-model-applications/)、[NIST AI RMF](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-ai-rmf-10)

## 甲方对接清单

首次对接需要收集以下信息，并由甲方指定负责人确认。

| 对接项 | 需要的最小信息 | 交付结果 |
| --- | --- | --- |
| 业务流程 | 一条订单或招聘服务流程、角色、时限、异常 | 流程图和验收案例 |
| 系统清单 | 系统名称、版本、接口方式、负责人 | 连接器方案 |
| 数据清单 | 对象、字段、来源、更新时间、分类 | 数据字典和字段映射 |
| 身份权限 | IdP、组织、群组、离职处理、管理员 | 身份与授权方案 |
| 模型边界 | 可出域字段、供应商、区域、保留期 | 模型环境契约 |
| 写入动作 | 允许动作、审批人、补偿和停用条件 | 工具契约和审批单 |
| 验收指标 | 准确率、来源、时延、越权和业务价值 | 试点验收表 |

没有甲方真实信息时，开发阶段使用合成数据和模拟器。模拟器输出必须标记来源为 `synthetic`，不能写成真实接入。


## 招聘数据的额外边界

候选人简历、联系方式、面试记录、背调和劳动关系资料按个人信息和项目机密处理。每次访问都要绑定客户项目、候选人同意记录、用途、角色和字段范围。候选人撤回同意、项目关闭、背调过期或员工离职时，系统重新计算可见范围并阻断后续引用和导出。

筛选规则必须来自甲方职位条件和已确认的岗位能力模型。系统保留规则版本、来源和人工调整记录，不能用未确认的敏感属性替代岗位相关条件。面试评分和背调结论分别存储，普通面试官不自动获得背调全文。推荐报告发送和录用、合同、派遣、工资、社保、离职写入属于高风险动作，必须经过对应角色审批和执行核验。
