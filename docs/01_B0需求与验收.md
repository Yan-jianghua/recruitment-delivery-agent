# 招聘交付与候选人管理 Agent B0 需求与验收

版本：V1.0
日期：2026-11-07
状态：需求基线，尚未实现或验收



## 领域优先级调整

从 2026-11-08 起，B0 首次开发主线调整为招聘与人力资源服务公司的职位交付流程。当前文件中 customer、sku、supplier、order 等对象保留为第二领域包，暂不作为 B0 首轮实现门槛。招聘领域的专属对象和验收以 [招聘服务公司领域需求](./08_招聘服务公司领域需求.md) 为准。

B0 首轮主线是：甲方职位订单 → 职位条件结构化 → 候选人授权检索 → 规则筛选 → 面试包 → 推荐报告预览 → 审计与权限撤回。

## 业务目标

企业员工能够在授权范围内查询制度和订单履约资料，获得带文档版本、结构化记录和数据时间的来源。系统能够把订单异常转成可复核的待办草稿，并在写入企业系统前要求明确的授权确认。

B0 只实现安全底座和一个可运行的业务切片。业务切片使用合成的外贸订单资料，覆盖客户、SKU、供应商、交期、库存、单证和物流节点。B0 不把真实企业接入、正式登录、自动发消息或自动修改订单标记为已完成。

## 目标角色

| 角色 | B0职责 | 允许动作 |
| --- | --- | --- |
| 知识管理员 | 导入和发布制度、规格书、供应商说明、单证模板 | 导入、版本管理、授权配置、查看处理状态 |
| 外贸/跟单员工 | 查询客户、商品、订单和制度资料 | 授权检索、查看引用、生成待办草稿 |
| 采购或物流负责人 | 复核供应商、库存、交期和物流异常 | 查看授权数据、确认草稿 |
| 审计员 | 检查访问、授权、模型和工具事件 | 只读审计查询 |
| 平台运维 | 管理运行健康和失败任务 | 查看指标、重试失败任务，不直接改业务状态 |

## B0 场景

### 场景 A：订单履约资料查询

员工输入“订单 ORD-1001 的交期、可用库存和出货所需单证是什么”。系统只在当前员工可读的文档和订单快照中检索，返回匹配片段、来源版本、记录时间和缺失字段。

### 场景 B：履约异常分级

系统根据订单、供应商、库存、生产进度和企业规则，生成“延期、缺货、质检不合格、单证缺失、物流节点异常”中的一种或多种异常，给出证据、责任角色和下一步待办。无法从授权数据确认时返回待核验。

### 场景 C：业务动作预览

系统生成创建跟进任务、补充单证、通知采购负责人或回写订单备注的预览。B0 只保存预览和审批记录，禁止直接调用真实系统写入。

## 需求

### RDA-B0-01 身份和租户

服务端根据演示令牌确定 `tenant_id`、`user_id`、角色和状态。请求正文中的身份字段不能覆盖服务端上下文。无效令牌返回 401，禁用主体返回 403 或统一的拒绝结果。

验收要求：员工甲、员工乙和管理员使用同一查询，结果按授权不同。跨租户文档、订单、任务和引用均不能被读取。

### RDA-B0-02 文档和版本

知识管理员可以导入 UTF-8 TXT 合成资料。资料建立文档、不可变版本、来源系统标识、内容哈希和处理状态。处理状态使用 `received → parsing → indexing → ready`，失败进入 `failed`。只有 `ready` 版本进入检索。

验收要求：空文件、错误编码、重复请求和处理失败都有明确结果。索引未完成时不返回半成品片段。

### RDA-B0-03 业务对象快照

B0 至少支持以下合成对象：`customer`、`sku`、`supplier`、`order`、`inventory_snapshot`、`document_requirement`、`shipment_event`。每个对象带租户、来源系统、外部 ID、更新时间和数据版本。

验收要求：同一个对象在不同版本中可区分，旧版本不会覆盖新版本。对象缺少来源或时间时，回答必须显示待核验。

### RDA-B0-04 资源级授权

管理员权限与正文或订单阅读权限分离。授权至少支持租户、文档、业务对象、主体和动作。默认拒绝。检索、引用、任务查询和预览每次都重新检查授权。

验收要求：撤销员工甲对订单资料的权限后，新检索、历史答案、引用和预览均被阻断。管理员没有被自动授予正文阅读权。

### RDA-B0-05 授权范围内检索

搜索接口只返回当前主体有权阅读且状态为 `ready` 的片段和对象。`query` 长度为 1 至 2000 个字符，`top_k` 范围为 1 至 20，额外字段拒绝接收。RAG 先确定可见集合，再执行关键词或向量匹配。

验收要求：无匹配时返回明确空结果。服务故障返回 503 或统一错误，不能伪装成空结果。结果项必须同时包含来源 ID、版本、定位和数据时间。

### RDA-B0-06 引用和事实核验

每条结论绑定 `source_id`、`version_id`、`locator`、`span_hash` 和 `as_of`。打开引用时重新校验租户、对象状态和阅读授权。引用无法定位或版本已撤销时返回受限或待核验状态。

验收要求：员工甲能够定位原文，员工乙对同一引用得到拒绝。模型生成的字段不得替代服务端保存的来源。

### RDA-B0-07 异常分级和待办草稿

规则服务根据订单快照和企业规则生成异常类别、严重级别、证据、责任角色、建议截止时间和下一步。Agent 可以提出解释和草稿，规则服务决定状态、权限和动作。

验收要求：延期、库存不足、单证缺失和物流超时各有一条正例。证据不足时不得生成确定性结论。草稿包含来源和规则版本。

### RDA-B0-08 受控动作预览

B0 只允许生成 `create_follow_up_task` 和 `add_order_note_preview` 两类预览。预览展示目标系统、对象、字段、影响范围、发起人、审批人和幂等键。保存预览不能改变外部系统。

验收要求：同一幂等键重复请求返回同一预览。不同内容复用同一幂等键返回冲突。任何客户端字段都不能扩大工具权限。

### RDA-B0-09 审计和可观测性

记录登录、授权决策、导入、检索、引用、模型调用、工具计划、审批、预览、失败、撤权和删除事件。事件至少包含主体、租户、资源、动作、结果、策略版本、请求 ID 和时间。日志不记录密钥、完整令牌和无必要的正文。

验收要求：从一条回答可以追到来源、权限判断和请求。审计记录不能由普通员工修改。

### RDA-B0-10 失败和恢复

导入或索引进程在中途退出后，任务进入可恢复状态。重复事件不重复发布版本。旧租约不能覆盖新任务结果。连接器模拟器超时或不可用时，系统返回明确失败并保留任务状态。

验收要求：失败、重试、取消和未知状态都保留在状态机中。不得直接把任务改成成功来绕过恢复流程。

## 验收数据集

使用明确标记的合成数据，建立两租户、三名演示用户、10 份文档、8 个订单、6 个 SKU、4 个供应商、5 个库存快照、6 个物流事件和 12 个异常案例。另建权限负例、提示注入样例、旧版本冲突样例和重复动作样例。

数据集需要保存版本号和哈希。调优样例与冻结验收样例分开，不能使用测试输入事后修改期望结果。

## B1 以后需求

B1 接入客户 OIDC 身份和一个真实系统只读接口。B2 增加客户领域规则包、实时订单查询、T0/T1 工具和客户评测集。B3 再考虑改价、改订单、发送消息或其他高风险动作，并要求审批、幂等、执行验证、补偿和甲方签收。每个阶段都要单独更新需求、接口、数据、安全和测试。

## 业务验收门槛

进入企业试点前必须具备业务负责人、数据负责人、IT 接入人和验收人。甲方确认首批样例、数据分类、目标系统、允许字段、业务指标和停用条件。未完成这些确认时，系统可以继续使用合成数据开发，但不能宣称企业已认可或已经完成真实接入。
