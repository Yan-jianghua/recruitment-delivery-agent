## 用户的第一批技术操作

用户进入开发阶段后按以下顺序执行，每次只完成一个可验证任务。

1. 核验当前分支、工作区和 Python 环境，确认 `docs/learning/WORKFLOW.md` 记录的状态与 Git 实际状态一致。
2. 从已核验的主分支创建 B0 实现分支，先实现服务端身份和权限规则。
3. 为合成对象、文档、版本、ACL、片段和审计事件建立最小数据模型和迁移。
4. 实现 TXT 导入、状态机、行号定位、授权检索和引用预览。
5. 先补权限负例、撤权、租户隔离和错误响应测试，再接入模型或 Agent 编排。
6. 实现筛选规则、面试包和推荐报告预览，保持外部写入关闭。
7. 加入模拟连接器、故障模式、幂等和任务恢复测试。
8. 运行冻结评测、生成报告、审查差异、提交并按仓库流程推进 PR。

用户每完成一项，就记录实际命令、分支、提交、测试输出和未解决问题。没有输出的步骤保留为待验证。

## 接口草案入口

### 查询职位与候选人上下文

```http
POST /api/v1/job-candidate-context
Authorization: Bearer <token>
Content-Type: application/json

{
  "job_id": "JOB-1001",
  "candidate_id": "C-1001",
  "include": ["client_company", "resume", "interview", "consent", "background_check"]
}
```

返回必须包含 `tenant_id`、职位和候选人版本、来源系统、`as_of`、可见字段和缺失字段。当前用户无权时，返回统一拒绝结果，不能暴露候选人或职位是否存在。

### 生成推荐或面试任务预览

```http
POST /api/v1/recommendations/preview
Idempotency-Key: demo-job-JOB-1001-candidate-C-1001-v1
Authorization: Bearer <token>
Content-Type: application/json

{
  "job_id": "JOB-1001",
  "candidate_id": "C-1001",
  "requested_action": "create_follow_up_task"
}
```

返回匹配结论、缺失条件、证据、面试或推荐责任人、规则版本、影响范围和预览。B0 不向外部系统写入。

## 对接访谈问题

首个企业对接时只需要收集能改变设计的事实。

- 当前职位或招聘服务流程从哪里开始，谁负责每一步，哪一步最容易遗漏。
- 使用哪些 ATS、招聘 CRM、HR、OA、企业微信、钉钉、飞书、合同或文件系统。
- 哪些字段必须实时，哪些字段可以定时同步，哪些字段属于敏感数据。
- 谁可以查看客户、价格、成本、供应商、工资或候选人信息、面试记录和背调结果。
- 哪一个低风险动作可以先做预览，谁审批，失败后如何补偿。
- 哪些问题可以用历史资料回答，哪些问题必须实时查询系统。
- 企业如何定义正确答案、拒答、升级和人工接管。
- 试点使用哪些脱敏样例、时间范围和指标，谁最终签收。

## 停止或回退条件

出现跨租户泄露、越权引用、未批准写入、陈旧版本覆盖、删除后仍可访问或未知外部副作用时，停止相关功能的继续开发和演示，保留审计证据，修复后重新运行对应验收。模型不可用、连接器不可用或证据不足时，进入人工回退流程。
