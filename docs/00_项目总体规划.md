# 招聘交付与候选人管理 Agent 项目总体规划

版本：V1.0
日期：2026-11-08
状态：规划基线，待首个目标企业确认

## 项目目标

项目首个业务领域面向招聘与人力资源服务机构，把甲方职位、岗位规则、候选人授权资料、面试记录、背调结果、推荐交付和入离职状态连接起来。系统为招聘顾问、HR、面试官和甲方提供带来源的筛选、面试准备、推荐报告、异常判断和流程待办，关键写入由授权人员确认后执行。外贸订单履约作为第二领域包，保留对产业企业的扩展能力。

项目的第一目标是交付一条可以在企业数据和权限边界内运行的职位交付与候选人证据流程。第二目标是建立一套可替换模型、可审计、可接入现有系统的企业 Agent 工程基础。第三目标是用真实脱敏样例、权限测试和业务指标获得 HR、技术面试官、企业负责人和甲方的可检查证据。

## 市场依据

调研样本的紧缺人才目录覆盖外贸经理、外贸业务员、海外业务拓展经理、外贸跟单员、外贸单证员、小语种翻译、电商运营、选品与采购、电商仓管、供应链经理、采购经理和海运操作员。岗位要求集中在客户开发、跨境平台、报价、供应商、合同、ERP、生产排程、库存、单证和物流协同。

样本人力资源服务机构公开提供网络招聘、招聘流程外包、猎寻、背景调查、劳务派遣、劳动关系托管和人力资源咨询。物流企业公开岗位要求建立客户档案、制定跨境物流方案、监控准确率和及时率、管理客服质量和培训。公开招聘活动样本还显示，制造、物流和跨境电商企业同时存在批量操作员、技术人才和电商岗位的招聘压力。

这些公开资料支持一个具体产品切入口。企业需要在多角色、多系统、多语言和高频异常中完成订单与用工协同，知识检索只有与企业规则、业务对象和系统状态连接后才会形成可衡量价值。招聘领域需求和市场研究的完整证据、来源和限制见 [招聘市场与 Agent 机会研究](./03_招聘市场与Agent机会研究.md)。

## 首个目标客户

首个目标客户是招聘服务机构、人力资源服务机构、劳务派遣和 RPO 团队，以及设有专业 HR 与面试流程的外贸、电商、物流和制造企业。优先选择同时存在以下条件的企业：

- 使用 ERP、CRM、OMS、WMS、TMS、OA、企业微信、钉钉或飞书中的至少一种系统。
- 有外贸、采购、跟单、单证、仓库或物流岗位，且岗位之间需要共享客户、商品、订单或状态信息。
- 愿意提供脱敏文档和只读接口，安排业务负责人、IT负责人和验收人。
- 能提供最近发生的订单异常、单证缺失、库存不足、延期或客户投诉案例。

首个行业不以“所有招聘企业”为边界。项目先把一个企业的对象模型、规则包、连接器、权限和评测集做深，再通过适配器复制到同类企业。

## 产品定位

产品定位为“面向招聘与人力资源服务团队的职位交付与候选人证据 Agent”。它的业务闭环是：

```mermaid
flowchart LR
    A[甲方职位订单] --> B[职位画像与条件核验]
    B --> C[候选人授权资料检索]
    C --> D[规则筛选与面试准备]
    D --> E[背调与合规材料]
    E --> F[推荐交付与入职待办]
    F --> G[业务系统写入预览]
    G --> H[授权审批与执行]
    H --> I[结果核验与审计]
```

B0 先完成文档版本、授权检索和引用预览，为后续业务对象和连接器建立权限底座。B1 加入企业身份和一个真实系统的只读接入。B2 加入职位与候选人领域模型、筛选规则、面试包和低风险工具，订单履约作为第二领域包在招聘领域 B0 通过后再进入开发。B3 只针对甲方确认的高价值动作增加审批、幂等、执行验证、补偿和回滚。

## 定制价值

定制价值来自五类企业资产的组合。领域对象模型定义客户企业、职位、候选人、简历版本、面试、背调、推荐和入离职状态的关系。规则包保存职位硬性条件、可放宽条件、候选人同意、面试评分、背调有效期和推荐升级条件。连接器把这些规则应用到客户已经在使用的系统。审计链把答案、来源、权限、审批和执行串起来。客户专属评测集把真实案例转成每次变更都要回归的质量门槛。

模型可以替换，企业数据、权限、规则、连接器和审计记录继续由企业控制。项目的差异化证据是同一任务集上更少的人工查找和复核、更少的跟单遗漏、更快的异常发现，以及对每个结论的来源和责任可追踪。

## 交付阶段

| 阶段 | 交付目标 | 必须证据 | 当前状态 |
| --- | --- | --- | --- |
| P0 规划与市场适配 | 完成招聘业务场景、目标客户、业务对象、风险和验收设计 | 市场研究、需求、架构、安全和验收文档 | 进行中 |
| B0 权限治理 RAG | TXT 导入、版本、ACL、授权检索、引用、撤权和越权测试 | 可复现运行、测试报告、审计事件 | 尚未实现 |
| B1 企业只读接入 | OIDC 身份、一个真实系统只读连接器、字段映射和同步状态 | 接口映射、断线测试、权限测试和部署说明 | 待客户条件 |
| B2 领域 Agent | 职位与候选人对象模型、筛选规则、面试包、T0/T1 工具和客户评测集 | 真实脱敏样例、来源支持率、拒答和工具审计 | 待 B1 |
| B3 受控写入 | 低风险业务动作、审批、幂等、执行验证和补偿 | 甲方签收、回滚演练、安全测试和运行手册 | 待 B2 |

阶段状态只代表规划或工程完成情况。企业认可、付费意愿、真实接入和商业结果必须由企业验收记录单独证明。

## 业务指标

首个试点由甲方从实际流程中冻结 20 至 50 条问题和 10 至 20 个异常案例，记录人工基线和 Agent 辅助后的结果。建议指标包括职位解析耗时、候选人筛选与复核耗时、面试安排遗漏数、推荐交付时延、筛选准确率、引用支持率、无依据拒答率、权限负例通过率、连接器失败恢复时间和人工复核率。具体阈值由甲方确认后写入验收单，当前不填充为已达成结果。

## 安全原则

系统采用服务端身份、租户隔离、资源级 ACL、默认只读、工具白名单、字段最小化、审批门禁、结构化审计和可回退执行。文档、邮件、网页、检索片段和模型输出都视为不可信数据。模型不能决定租户、对象可见性、审批或写入权限。企业接入和安全要求见 [企业接入与安全基线](./05_企业接入与安全基线.md) 与 [企业级定制 Agent 架构与安全边界](./04_企业级定制Agent架构与安全边界.md)。

## 认可路径

HR 需要看到岗位与业务流程的对应关系、角色权限和数据边界。技术面试官需要看到可运行的 API、数据模型、错误路径、权限负例、连接器契约、Git 和测试证据。企业负责人需要看到业务指标、异常处理、成本和运行责任。甲方需要看到脱敏样例接入、来源可追溯、审批与审计、停用和回滚。

本项目把这些材料作为交付物。材料可以支持评审和面试，不能替代真实企业签收或安全认证。

招聘领域的详细需求见 [招聘服务公司领域需求](./08_招聘服务公司领域需求.md)。

## 当前已知限制

当前仓库没有业务源代码、迁移、前端应用、CI、部署和真实连接器。现有 B0 需求与技术设计是草案，文档中的安全和集成要求还没有代码证据。仓库审计见 [REPO-AUDIT-2026-11-07](./REPO-AUDIT-2026-11-07.md)。

招聘领域的对象、授权、候选人同意、面试评分和背调状态必须与需求、安全基线、评测集和工作流同步更新。

## 规划变更规则

新增业务对象、连接器、角色、工具、写入动作或数据分类时，必须同时更新需求、接口、数据模型、安全基线、评测集和工作流记录。任何“已完成”都需要对应提交、运行结果或企业签收证据。
