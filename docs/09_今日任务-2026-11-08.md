# 今日任务：RDA-B0-001 安全底座启动

日期：2026-11-08  
任务状态：准备开始  
目标分支：feat/rda-b0-001-security-foundation

## 今日目标

为招聘职位交付 Agent 建立第一条可开发、可测试的安全底座，覆盖：

- 服务端识别演示用户和租户。
- 候选人同意记录与撤回状态。
- 客户项目、职位、候选人和简历版本的最小数据关系。
- 资源级读取权限判断。
- 跨租户、跨客户项目和撤回同意后的拒绝路径。

今日不接入真实企业系统，不调用外部模型，不执行录用、合同、派遣、工资、社保或消息发送。

## 今日最小实现范围

### 领域对象

先实现以下对象的最小字段，不增加额外业务字段：

| 对象 | 必要字段 |
| --- | --- |
| tenant | id、name、status |
| user | id、tenant_id、role、status |
| client_company | id、tenant_id、name、status |
| job_order | id、tenant_id、client_company_id、status |
| candidate | id、tenant_id、consent_status、status |
| consent_record | id、tenant_id、candidate_id、purpose、scope、status、version |
| resume_version | id、tenant_id、candidate_id、version_no、source、content_hash、status |
| resource_acl | tenant_id、resource_type、resource_id、subject_id、action、status、version |

### 必须先写的规则

1. 请求正文中的 tenant_id、user_id、role 不能覆盖服务端识别结果。
2. 没有同租户关系时拒绝访问。
3. 没有候选人有效同意时，候选人资料和简历版本不可检索。
4. 同意撤回后，新请求和历史引用入口都重新检查状态。
5. 管理职位权限不自动获得候选人正文阅读权。
6. 所有拒绝结果保存主体、资源、动作、策略版本和 request_id。

## 今日验收

| 编号 | 用例 | 预期结果 |
| --- | --- | --- |
| RDA-001 | 员工甲读取同租户且同项目候选人 | 允许，返回授权字段 |
| RDA-002 | 员工甲读取其他租户候选人 | 拒绝，不泄露对象存在信息 |
| RDA-003 | 员工甲读取其他客户项目候选人 | 拒绝 |
| RDA-004 | 候选人没有有效同意记录 | 拒绝简历正文 |
| RDA-005 | 候选人撤回同意后再次读取 | 拒绝正文和引用 |
| RDA-006 | 客户项目管理员读取候选人正文 | 按独立 ACL 决定，不能自动放行 |
| RDA-007 | 修改请求中的 tenant_id 或 user_id | 服务端身份不改变 |
| RDA-008 | 重复提交同一同意版本 | 幂等返回相同结果 |
